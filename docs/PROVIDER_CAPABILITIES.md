The hosted NVIDIA model card does not make self-hosted NIM `guided_json`, thinking flags or any other vendor's parameters safe to send. Spot sends only the reviewed chat fields. No direct Z.ai endpoint, remote arbitrary base URL, auto-picked “latest” model, vision or callable tool list. Adding a model requires review of its actual endpoint and new tests. API context windows are not used as a target: the shortlist is6 records, descriptions160characters and cloud query600characters; local query400characters. Endpoint/account maximums remain a live-smoke precondition; Spot's smaller request bounds apply regardless.

Prompt v4 gives the CPU Qwen an indices-only task (1–3 unique integers in0..shortlistLength−1). The server binds those indices to immutable source IDs/category evidence, constructs allowed activity/duration suggestions, then validates the same grounded choice contract. Cloud adapters retain explicit POI/evidence-ID JSON. This avoids hundreds of long identifier tokens and prevents the small model from supplying factual prose. The server enforces complete mandatory journey stages even if Qwen ranks only one category. Restaurant type and every requested cuisine require matching source evidence; menu/availability/booking are not inferred. The verbose-ID experiment and R1 promptv3 are historical, not current R2 proof. Local query-vector cache retains validated vectors under SHA256(query+embedding spec), maximum32 entries/5minutes, in process memory only; no raw query/origin or persisted history.

Cloud call requires all of APP_MODE=live, ALLOW_LIVE_API=true, reviewed endpoint/model, key, AI_RUN_ID, permission expiry no more than24h ahead, positive finite run/day budgets, request count and input/output upper rates. Empty is not unlimited; key presence is not authorization. Failover needs ALLOW_PROVIDER_FAILOVER=true and a separately configured authorized provider. Embedding space never changes when generation provider changes.

Each cloud attempt reserves the entire conservative upper estimate before fetch in a persisted run/day ledger under ignored work/private. Exclusive filesystem locking shares limits across local processes. Repairs/retries/failover use the same ledger; timeout/unknown billing is never refunded as zero. Actual billing remains null unless known; token counts are stored only if returned. The cost estimate includes UTF-8 body bytes as a conservative input-token bound plus1024overhead. Set provider-side spending limits as well: price assumptions and provider billing cannot be mathematically guaranteed by a client. Multi-machine deployment needs a transactional central ledger; this local prototype is not deployed.

Two generation calls maximum per user search: primary plus one repair OR retry OR failover. Retry only429/5xx, never401/403; Retry-After longer than remaining retry allowance returns degraded rather than retrying early. Shared request deadline, client cancellation, concurrency2, circuit opens after3transient failures for30s. Server binds IDs/evidence/activity/time again before rendering; no free factual prose or hidden reasoning is accepted.

`doctor`, `verify`, `eval`, `smoke` are offline by default and remove cloud credentials. `npm run eval:live` additionally requires SPOT_LIVE_SMOKE=true; invoking it without authorization fails. No cloud live-smoke was performed for this delivery. Local Qwen requests incur no provider API fee; CPU/RAM/electricity and map/photo/routing network availability still matter.
