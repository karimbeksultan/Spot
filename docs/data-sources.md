# Данные, изображения и маршруты Spot

## Расширение 18.10.2026

Первый запрос OpenStreetMap/Overpass вернул 1771 объект в bbox `50.95,71.2,51.3,71.7`; контрольный count совпал, усечения нет. После проверки stable IDs, известного дубля и access=private/no получено 1705 POI. Второй ограниченный запрос вернул 622/622 объектов и добавил 465: 178 ресторанов, 125 точек быстрого питания, 93 бара, 17 рынков, 14 общественных центров, 13 пабов, 10 кинотеатров, 6 центров искусств, 5 фонтанов и 4 точки мороженого. Все они имеют category=other и явный исходный amenity-тип в описании; ресторан не объявляется кафе. Два закрытых объекта исключены, 154 безымянных объекта не превращены в выдуманные заведения, изменение известного ID отложено.

Итог — **2170 сохранённых POI**, из них **2165 доступны для выдачи**. В полном корпусе 357 кафе, 179 парков/садов, 346 площадок, 673 скамейки, 72 достопримечательности, 8 музеев и другие места. Пять объектов с явным `addr:city=Косшы/Қосшы` помещены в проверяемый карантин `data/scope-exclusions.json`: они не участвуют в local/Supabase выдаче, исходные payload и векторы не удалены. Bbox не является точной административной границей, и отсутствие city-тега не доказывает принадлежность. Безымянные наружные объекты имеют явно производные названия с OSM ID. Неизвестные часы, цены и удобства не заполняются догадками. Это ограниченное покрытие OSM, не все существующие объекты города.

Исходные 98 записей и 60 фото, а затем все 1705 payload сохранены точно. 338 записей содержат текст часов, 195 — адрес, 0 — подтверждённую розетку. fetchedAt не выдаётся за confirmedAt. Последний берётся только из source check_date и не означает независимого осмотра командой. Снимки: `data/raw/overpass-astana-city.json`, `overpass-astana-city-extension.json`; provenance: `data/provenance.json`; сохранение прежних записей: `data/reports/city-import-merge.json`, `city-extension-merge.json`.

Google Maps просмотрен для исследования и доступен кнопкой ручной проверки карточки через официальный keyless Maps URL. Карточки, отзывы и фотографии Google не копировались в корпус или обучение. Восемь операторских источников разобраны в `docs/OFFICIAL_SOURCE_ENRICHMENT_RESEARCH.md`; неподтверждённые филиалы, сложные исключения часов и изображения с unknown license не импортированы.

Локальный индекс: **2170 векторов по 768 измерений**, embeddinggemma/version1. При последнем расширении 1705 совместимых строк использованы повторно, 465 новых строк построены по 425 разным текстам за 54 успешных локальных batch-запроса. Предыдущий этап использовал 98 старых строк и создал 1607 новых по 450 текстам за 57 запросов; пробный запуск до оптимизации не выдается за итоговый. Одинаковые описания безымянных объектов используют общий вектор, сохраняя разные ID/координаты. Веса не обучались, платных API и remote DB writes не было. `data/local-index/metadata.json` фиксирует хеш бинарных векторов и документов, `data/reports/local-index.json` — последний запуск.

Проверено 16 октября 2026 года. Это датированный снимок, а не гарантия текущей работы каждого места. Автоматический сбор дал 98 POI: 57 кафе, 11 парков/садов, 18 достопримечательностей, 11 прочих мест и 1 площадку. У 29 объектов были часы в исходной записи. После ручной проверки фотографий 14 мест получили 60 снимков; 84 места пока без подтверждённых фото. Подтверждённых розеток и музеев в этих трёх небольших зонах не оказалось. Актуальные отчёты — `data/reports/quality.json` и `photo-enrichment.json`. Наличие часов в OSM не означает независимого подтверждения их актуальности.

## Повторяемая цепочка

Из корня репозитория:

```powershell
npm run data:collect
npm run data:validate
# Повторная нормализация разрешенного снимка без обращения к источникам:
npm run data:collect -- --from-snapshot
# Поиск кандидатов ничего автоматически не прикрепляет:
npm run data:photo-discover
# Обновление только фото по проверенным связям, без пересоздания embeddings:
npm run data:photos
npm run data:photos -- --from-snapshot
```

`collect.ts` запрашивает 3 небольшие зоны: Expo/Mega, Ботанический сад и центральный левый берег. Сырые ответы записываются в `data/raw/overpass.json` только после успеха всех зон. Затем `normalize.ts` проверяет координаты Астаны, создает устойчивый ID `osm:тип/id`, удаляет повторения ID и одинаковые имена одной категории в радиусе 35 м. Двуязычный дубль Mega (`node/4965336822` → `way/499328514`) отмечен в коде и отчете как ручное сопоставление. Иные близкие названия не объединяются без доказательства. Описание — короткое представление категории из тегов; это не скопированная рекламная статья.

`photos.ts` сопоставляет лишь заранее проверенные ID/файлы из `data/photo-links.json`. API обогащение автоматизировано, а решение о соответствии конкретному месту записано отдельно. Если metadata недоступны или лицензия/автор/статус непригодны, остается «Фото пока нет». Поисковый запрос по имени не прикрепляет случайное фото автоматически.

Расширение галерей: 623 географических кандидата, категории точных мест, адреса и визуальная проверка. Сохранены автор, страница исходника, индивидуальная лицензия и русские подписи ракурсов. Кадры могут быть историческими; дата фото не подтверждает нынешнее состояние заведения. Панорамы из Байтерека подписаны как виды со смотровой. Общие интерьеры Хан Шатыра не прикреплены к отдельным аттракционам. Для 57 кафе отдельно проверялись филиалы: подтверждены Drinkit и MADO. Подробности: `photo-cafe-research.json`, `photo-landmark-research.json`, `photo-extra-research.json`. Ответы Commons 429 останавливали исследовательские запросы; отсутствие подтверждённого кадра не означает отсутствия любых фотографий в интернете.

Карточка показывает до 10 уникальных фотографий с навигацией кнопками и клавиатурой. Загружается выбранный кадр; недоступный пропускается. «Фото пока нет» означает отсутствие проверенных данных, «Фото не загрузились» — недоступность всех URL. Перенос в разрешённую Spot выполнен как обновление только `payload.photos`; поисковые факты, хеши и 98 векторов сохранены.

`contentHash` не зависит от даты загрузки. Изменение фактов обновляет хеш; фотографии не входят в текст embeddings. `confirmedAt` остается `null`, если исходный `check_date` не задан. Дата редактирования OSM, дата фото и время HTTP-загрузки не подменяют дату проверки места.

## Основная БД и embeddings

После выбора и настройки разрешенной тестовой базы, применения миграции и локального заполнения `.env.local`:

```powershell
npm run data:upsert
npm run data:embed
```

Запись идет по устойчивому `pois.id`; доказательства и авторство фото включены в `payload`. Отдельная `ingestion_runs` хранит только технические счетчики. Для CLI нужен серверный `SUPABASE_SECRET_KEY` или `SUPABASE_SERVICE_ROLE_KEY`; эти значения не выводятся. Для внешней базы скрипт дополнительно требует `SPOT_APPROVED_DATABASE_HOST`, равный точному хосту уже отдельно разрешенной пользователем базы. Установка переменной не заменяет разрешение. Локальные `localhost`/`127.0.0.1` принимаются автоматически.

После отдельного разрешения пользователя создан и заполнен только новый проект **Spot `jlyqncuqkqhkkopgflzl`**. Через Supabase MCP выполнены два атомарных upsert одного снимка: оба обработали 98 POI, после повторения в БД осталось ровно 98 уникальных ID. Секретный ключ не экспортировался. Под эффективной ролью `anon` успешно прочитаны 98 POI и 15 мест в радиусе 1 500 м от Mega через `spot_nearby`. Реальная попытка INSERT под `anon` отвергнута с SQLSTATE 42501; INSERT/UPDATE/DELETE и чтение ingestion_logs недоступны, тестовых строк не осталось. Это тест роли БД, отдельная проверка публичного HTTP API описывается в общем отчете. Доказательства: `data/reports/supabase-ingestion.json`.

Используется только локальный Ollama `/api/embed`, модель `OLLAMA_EMBED_MODEL` (по умолчанию `embeddinggemma`), 768 измерений и версия `1`. [Официальный API](https://docs.ollama.com/api/embed) проверен. Существующие документы пропускаются при совпадении хеша, модели, размерности и версии. Другие размерность/версия отвергаются, пока схема и retrieval не обновлены вместе. Ответ проверяется по имени модели, размерности, конечным числам и ненулевому вектору.

16 октября локальная Ollama 0.40.5 реально создала **98 векторов embeddinggemma** на CPU. Через разрешенный MCP они записаны только в Spot; readback подтвердил 98 уникальных документов, 768 измерений и 98 актуальных хешей источника. Повторный upsert 14 документов изменил 0 строк, общее количество осталось 98. `spot_search` под ролью `anon` с реальным вектором документа Аллеи и текстом «парк» вернул пять объектов в радиусе 1 500 м, начиная с Аллеи. Это проверка корпуса и RPC; проверка генерации ответа приложения учитывается отдельно. Подробности: `data/reports/embedding.json`, `docs/local-model-audit.md`. Резервный снимок всегда имеет отдельную маркировку.

## Карта — отдельный источник

MapLibre — библиотека рендеринга. Для локального демо используются публичные raster tiles `https://tile.openstreetmap.org/{z}/{x}/{y}.png` с видимой атрибуцией. [Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/) требует HTTPS, корректный браузерный Referer/User-Agent и соблюдение кеша. Массовая загрузка, prefetch города и обещание offline-карты запрещены. Не запускайте массовые тесты панорамирования карты. URL должен оставаться конфигурируемым. Провайдер видит IP и запрошенные тайлы; это раскрывает просматриваемую область.
