## Воспроизводимость

- Нормализованные места: [data/pois.json](../data/pois.json).
- Происхождение фактов: [data/provenance.json](../data/provenance.json).
- Исходные городские ответы: [первый сбор](../data/raw/overpass-astana-city.json) и [расширение](../data/raw/overpass-astana-city-extension.json).
- Проверка корпуса: [quality.json](../data/reports/quality.json).
- Локальный индекс: [metadata.json](../data/local-index/metadata.json), `embeddinggemma`, 768 измерений, версия 1, 2170 векторов.

Сначала просматривают план импорта; сетевой сбор и изменение корпуса выполняются отдельным явным запуском:

```bash
npm run data:collect-city -- --from-snapshot --dry-run
npm run data:validate
npm run data:index-local -- --dry-run
```

`--dry-run` индексатора не вызывает модель и не пишет файлы. Реальное построение индекса использует локальный Ollama; совместимые строки переиспользуются по ID, хешу, модели, размерности и версии. Импорт не удаляет исходные записи после частичного сбоя. Фото не входят в текст embedding-документа.

Supabase необязателен. `data:upsert` / `data:embed` требуют серверных ключей и точного разрешённого хоста БД через `SPOT_APPROVED_DATABASE_HOST`; установка переменной не заменяет разрешение на запись. Основной локальный режим использует включённый файловый снимок.

## Почему операторские сведения не импортированы автоматически

Проверка сайтов операторов 18 октября выявила неоднозначные филиалы CoffeeBoom, отдельные режимы оранжерей и парка, исключения санитарных дней и различие здания NUR Alem с текущей экспозицией. Эти кандидаты не внесены в корпус. Часы кассы и экспозиции нельзя смешивать; совпадение бренда не подтверждает филиал. Изображения с неизвестной лицензией не переносились. Перед расширением нужны точный объект/вход, источник каждого поля, дата и поддержка исключений расписания.
